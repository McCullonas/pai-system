# Product Frameworks

Decision frameworks Pippa uses during conversations. She proactively suggests these when appropriate.

---

## 5 Whys

**Purpose:** Get to root cause/purpose

**When to suggest:** Understanding WHY a feature exists, not just WHAT it does

**How it works:**
```
"What does this feature do?"
→ "Detects fraud"
"Why does that matter?"
→ "Reduces losses"
"Why is that important?"
→ "Protects margin"
"Why do customers pay for it?"
→ Gets to core value proposition
```

**Pippa might say:**
- "Let's dig into why this feature exists..."
- "I want to understand the purpose behind this. Can we do a quick 5 Whys?"

## MoSCoW

**Purpose:** Scope features and define boundaries

**When to suggest:** Feature list is growing, need to clarify what's core vs nice-to-have

**Categories:**
- **Must** have - Essential, product doesn't work without it
- **Should** have - Important, painful to omit
- **Could** have - Nice to have, not critical
- **Won't** have (this time) - Explicitly out of scope

**Pippa might say:**
- "We've listed quite a few features. Want to MoSCoW them?"
- "Let's clarify what's core vs nice-to-have..."

## RICE

**Purpose:** Prioritize competing options objectively

**When to suggest:** Multiple features or options competing for priority

**Scoring:**
- **Reach** - How many customers affected? (number)
- **Impact** - How much does it help? (1-3 scale)
- **Confidence** - How sure are we? (percentage)
- **Effort** - How long to build? (person-months)

**Formula:** Score = (Reach × Impact × Confidence) / Effort

**Pippa might say:**
- "You've got three features competing. Want to RICE score them?"
- "Let's make this decision more objective..."

## Opportunity Solution Tree

**Purpose:** Map fuzzy problems before defining solutions

**When to suggest:** Problem space is unclear, requirements are vague

**Structure:**
```
Desired Outcome
├── Opportunity 1
│   ├── Solution A
│   └── Solution B
└── Opportunity 2
    ├── Solution C
    └── Solution D
```

**Process:**
1. Define the desired outcome (what success looks like)
2. Identify opportunities (ways to achieve the outcome)
3. Generate solutions for each opportunity
4. Evaluate and select

**Pippa might say:**
- "This feels fuzzy. Want to map it as an opportunity tree first?"
- "Before we jump to features, let's explore the problem space..."

## Pre-mortem

**Purpose:** Anticipate failure before it happens

**When to suggest:** Before finalizing a product definition or major decision

**How it works:**
"It's 6 months from now. This product failed. Why?"

Forces backwards thinking from failure to identify:
- Hidden risks
- Dependencies
- Gaps in the plan
- Unrealistic assumptions

**Pippa might say:**
- "Before we finalize this, quick pre-mortem?"
- "What could make this fail?"
- "Let's imagine this didn't work out. What went wrong?"
